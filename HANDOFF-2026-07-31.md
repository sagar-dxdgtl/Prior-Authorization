## §1. Two regressions today were PAYER-SIDE, not ours — expect more

Both happened *during a single session*, on code that had passed live minutes earlier. This is the
operating reality of driving other people's portals; there is no version of this that is immune.

* **UHC shipped a new guest shell.** A modal headed *"Welcome to the new guest experience!"* appeared
  over the coverage-type cards. It carried none of the two `data-testid`s observed 2026-07-28, so
  `_dismiss_overlays` walked past it and every later click landed on the overlay. All three UHC rows
  died at `coverage type 'Medicare' NOT clickable` after ~198s of retries. The query that returned
  OUT_OF_NETWORK three consecutive times at 19:16 was failing by 22:00 with `uhc_findcare.py`
  untouched. **Diagnosed from the driver's own screenshot** — file one on every failure path.
  Fixed by adding a dialog-scoped `Get started` handle plus generic modal/coachmark close fallbacks,
  and keeping the old testids. **A vendor testid does not survive a redeploy; the button a human is
  asked to press does.**
* **Aetna's results grid was being read while still painting.** `_cards` read the DOM the instant the
  results route opened, with no wait, so a rendered-but-unpainted page was indistinguishable from a
  genuine absence — reported as UNKNOWN with "no result card matched". The screenshot showed Aetna's
  own `Loading…` spinner with the plan correctly pinned. Now polls, and stops early once the spinner
  clears so a genuinely empty set does not cost the ceiling.

⚠️ `_dismiss_overlays` also caught only Playwright exceptions, so an element detaching mid-check
aborted the remaining handles. Best-effort dismissal must try **every** handle.

  On a Medicaid row that is the difference between a Medicaid and a dual-eligible answer.

Stored on `portal_captures.networks_accepted` (JSONB, GIN-indexed, migration 0040) and rendered in
the Portal Proof tab. Queryable without re-walking:

    SELECT npi FROM portal_captures WHERE networks_accepted @> CAST('["Alliance HMO"]' AS jsonb)

⚠️ **NULL means "not asked", never "in no networks".** Only a NON-EMPTY list licenses reading absence
from it as evidence.

**An OON verdict now runs a second, un-pinned pass** to get the list — because the list lives on the
result CARD and a walk proving absence renders no card. **It must be a FRESH CONTEXT, not a reload.**
Measured: pinned load → chip `Statewide/National PPO`; `about:blank` → generic launch → still pinned;
cookies + localStorage + sessionStorage wiped → still pinned; **fresh context → `Choose a network`**.
The pin lives somewhere `clear_cookies()` does not reach. The first build of this silently returned
nothing and cost a minute doing it.

silently relying on the dead 10–15s. UHC's post-plan `search.wait_for(15_000)` started failing →

## §5. ⚠️ DEMO RISK — read before showing rows 1, 5, 7, 11 on real patient data

**None of those four ran on a real 271.** They ran on the sheet's `Insurance` string. A real 271 will
carry a different string and pin a different network. Whether that breaks you depends on direction:

> **Absence generalises downward. Presence does not.**

* **Rows 5 and 7 are ROBUST.** Both are OON by absence, both pinned at a BROAD level. Row 5's own
  note: *"absent from the licensee-level directory also means absent from every narrower BCBSIL
  product network inside it."* A narrower real plan can only make the absence more certain.
* **Row 11 is the FRAGILE one.** It is IN, on a network we **defaulted to** — `Open Choice® PPO` —
  because "Aetna Commercial" names no product. The driver's own note warns: *"presence in the broad
  network does NOT imply presence in a narrower one (APCN, APCN Plus, Savings Plus)."* A real narrow
  plan could legitimately flip this to OON. Not a bug — a more accurate answer, mid-demo.
  Mitigation: 07-29 verified the same provider on `Aetna Choice POS II (Open Access)` → IN, so two
  products are known good.
* **Row 1 may IMPROVE.** Medicare 271s usually carry a contract/PBP id (H-number), which is
  **identifier-grade** and pins via tier 1 rather than token overlap — stronger than the sheet string.

**Operational risks, all observed today:** portals change without warning (§1, twice in one session);
Cigna's WAF blocks after ~4 walks in 10 minutes, so **do not rehearse a row repeatedly right before
showing it**; walks run 44–180s, and row 5's second pass makes an OON longer.

**Recommended before any live demo:**
1. **Dry-run the four with realistic 271-style plan strings**, including a contract id for the
   Medicare rows. ~20 minutes across four payers. Learn which strings pin *before* an audience does.
2. **Build a pre-flight plan check** — verify the string pins a network BEFORE walking, so an
   unpinnable plan fails in 2s with "this plan names no network I can find" instead of 90s ending in
   UNKNOWN. Converts the worst demo failure (long silence, then a shrug) into a fast explainable one.
   NOT BUILT.

## §7. Source freshness — measured, and what it does NOT prove

| source | data date | age on 2026-07-31 |
|---|---|---|
| member portals (UHC/Molina print it; AZ Blue 07/30; Aetna *"6 days per week"*) | 07-30/31 | **0–1 d** |
| HCSC FHIR (`Bundle.meta.lastUpdated`) | 2026-07-13 | **18 d** |
| TiC MRFs (`source_built_at`) | 06-14 … 07-05 | **26–47 d** |

That ordering is regulation, not luck: NSA ~2 business days for member directories, CMS
Interoperability 30 days for directory APIs, TiC monthly.

⚠️ **Every clock starts when the payer RECEIVES the information, never when the contract changed.**
Freshness ranks sources; **it never proves currency**. 118 of 120 facts were backfilled with
`source_built_at` parsed from their labels (the two undated are Oscar's net 065, which carries real
contract dates instead).

**No public source carries provider↔commercial-payer contract terms.** Verified today: CMS publishes
none (PECOS/Care Compare are provider↔*Medicare*); the CMS TiC schema gives `provider_references`
**no date fields at all** (range-read the BCBS IL header — only a file-level `last_updated_on`);
APCDs are 6–12 months stale, ERISA-preempted for self-funded plans, and **Illinois has none**;
Illinois DOI network-adequacy filings are aggregate ratios, not physician rosters.
**The only contract-grade artifacts are an 835/ERA remit or a member EOB** — both private, both one
step from the client. The system currently speaks **270/271 only**; no 835/837/276/277 support.
